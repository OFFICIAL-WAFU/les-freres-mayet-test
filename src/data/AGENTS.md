# Data layer rules
- Clients are stored in the `clients` table (RLS owner_id = auth.uid(), no delete, anon revoked, server-managed dates); src/data/clients.ts is the only access point. Why: step 9 moved clients to durable per-owner storage while entreprise/devis stay in memory.
- Client edits use optimistic concurrency (update … where updated_at = version read) and creations use a client-generated stable UUID per attempt. Why: avoid silent overwrites across tabs and duplicates on retry.
- Catalogue articles are stored in the `articles` table (same RLS/grant/trigger pattern as clients, price in integer cents, unique (owner_id, lower(trim(reference))) incl. archived); src/data/catalogue.ts is the only access point. Why: step 10 persisted the catalogue; quote lines copy article values and stay independent.
- Company profile is stored in the `entreprises` table (one per owner via UNIQUE(owner_id), same RLS/no-delete/trigger pattern, capital numeric(15,2) nullable); src/data/entreprise.ts is the only access point; preview/PDF use only the saved row. Why: step 11 persisted the company profile.
- Quote drafts are stored in `devis` + `devis_lignes` (RLS per owner, lines only via own quote, client/article ownership checked by triggers, line amounts recomputed by trigger); every save goes through the atomic SQL function enregistrer_brouillon(id, version, payload) (SECURITY INVOKER, integer version for concurrency, per-owner counter for BROUILLON-NNN); src/data/documents.ts is the only access point; fake demo documents only shown when Réglages demo mode is on. Why: step 12 persisted drafts atomically.
- Quote finalisation goes only through SQL finaliser_devis(id, version) (idempotent, per-owner/type/year counter DEV-LFM-AAAA-NNNNN in Europe/Paris, frozen entreprise_copie); triggers lock finalised quotes and their lines; preview/PDF of finalised quotes use only frozen data. Why: step 13 immutable finalised quotes.
- Invoice drafts are stored in `factures` + `factures_lignes` (same RLS/trigger pattern as devis, UNIQUE(devis_source_id) = one invoice per quote, client/source/reference immutable, separate per-owner counter BROUILLON-FAC-NNN, no definitive invoice counter); created only via idempotent SQL preparer_facture(devis_id) (locks the quote row, requires finalised quote, copies frozen client + lines) and saved via enregistrer_facture(id, version, payload); src/data/documents.ts is the only access point. Why: step 14 invoice drafts from finalised quotes without duplicates.
- Invoice finalisation goes only through SQL finaliser_facture(id, version) (idempotent, row lock, shared per-owner/type/year counter with type 'facture' → FAC-LFM-AAAA-NNNNN in Europe/Paris, frozen entreprise_copie); triggers lock finalised invoices and their lines and forbid deletion; preview/PDF of finalised invoices use only frozen data. Why: step 16 immutable finalised invoices.
- Deposit invoices (factures d'acompte) live in `factures` with nature='acompte' (UNIQUE(devis_source_id, nature), own BROUILLON-ACP-NNN counter, pourcentage numeric(5,2)); lines are computed only by SQL acompte_calcul/acompte_ecrire_lignes (per-VAT-rate base × %, half-up rounding) via preparer_acompte / enregistrer_acompte; deposits are finalised through finaliser_facture (shared FAC-LFM counter, recomputed amounts checked, refused if the quote already has a finalised ordinary invoice); triggers block direct line/percentage writes. An ordinary invoice whose quote has a deposit can only be finalised once the deposit is finalised: finaliser_facture freezes the deposit per-rate amounts in factures.deduction + acompte_deduit_id (unique), refuses overflow per rate, and the balance is always computed by exact per-rate subtraction (deduction_live for drafts). Why: step 17 multi-VAT deposits without duplicates.
- Payments are stored in `reglements` (RLS per owner, no delete, writes only via SQL enregistrer_reglement(id, facture_id, …) — idempotent on client-generated id, locks the invoice row, refuses drafts and overpayment — and annuler_reglement(id, motif) which keeps the row and marks it cancelled); amount due = frozen TTC minus frozen deduction; src/data/reglements.ts is the only access point. Why: step 20 manual payments without duplicates or overpayment, never touching frozen invoices.
- Credit notes (avoirs) are stored in `avoirs` (RLS per owner, no delete, UNIQUE(facture_source_id) = one per invoice, own BROUILLON-AV-NNN counter, lines/totals copied as a frozen jsonb snapshot of the source invoice); created only via idempotent SQL preparer_avoir(facture_id, motif) (finalised ordinary invoice without deposit deduction) and edited via enregistrer_avoir(id, version, payload) which may change only date, motif and remarks (trigger-enforced); finalised only via idempotent SQL finaliser_avoir(id, version) (locks the source invoice first, same order as enregistrer_reglement, checks amounts equal the source, per-owner/year counter type 'avoir' → AV-LFM-AAAA-NNNNN, frozen entreprise_copie, then fully immutable); only finalised avoirs reduce the source balance: net = due − credited − active payments, remaining = max(net,0), customer credit = max(−net,0), and enregistrer_reglement refuses payments on a fully credited invoice; src/data/documents.ts is the only access point. Why: steps 21–22 total credit notes without refunds.
